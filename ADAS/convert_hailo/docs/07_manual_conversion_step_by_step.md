# Manual Conversion Step by Step

This document reconstructs the full manual conversion flow implemented by:

- `convert_flow/run_convert.sh`
- `convert_flow/run_hailo_docker.sh`
- `convert_flow/scripts/compile.sh`

Use this guide when you need to run the conversion manually, debug a specific stage, or rerun only part of the pipeline without the interactive orchestrator.

## What this manual flow produces

At the end of the process, `shared_with_docker/` should contain:

- `best.onnx`
- `calibration_images/`
- `nms_config.json`
- one or more `.har`
- one `.hef`

## 1. Go to the conversion workspace

```bash
cd /home/heolivei/Team5_Senna_Tech/convert_hailo
```

## 2. Create and load the local configuration

If `.env.hailo` does not exist yet:

```bash
cp .env.hailo.example .env.hailo
```

Edit `.env.hailo` and set the absolute paths for your machine.

Then load the variables:

```bash
set -a
source ./.env.hailo
set +a
```

The scripts expect at least:

```bash
echo "$BASE_PROJECT"
echo "$VENV_NAME"
echo "$SHARED_DIR"
echo "$CONTAINER_NAME"
echo "$DOCKER_IMAGE_NAME"
echo "$DOCKER_TAR_FILE"
```

## 3. Define the run and model scale

Choose the training run folder under `${BASE_PROJECT}/runs/` and the target Hailo model name.

Example:

```bash
RUN_NAME="train-seg-01"
MODEL_BASE="yolov8n_seg"
MODEL_PT="${BASE_PROJECT}/runs/${RUN_NAME}/weights/best.pt"
ARGS_YAML="${BASE_PROJECT}/runs/${RUN_NAME}/args.yaml"
DATASETS_DIR="${BASE_PROJECT}/datasets"
NUM_CALIB_IMAGES=1024
```

Supported `MODEL_BASE` values, matching `run_convert.sh`:

- `yolov8n_seg`
- `yolov8s_seg`
- `yolov8m_seg`
- `yolov8l_seg`
- `yolov8x_seg`

## 4. Validate the required inputs

```bash
test -f "$MODEL_PT"
test -d "$VENV_NAME"
test -d "$DATASETS_DIR"
```

If you want visible confirmation:

```bash
ls -lh "$MODEL_PT"
ls -ld "$VENV_NAME"
ls -ld "$DATASETS_DIR"
```

## 5. Prepare and clean `shared_with_docker`

This reproduces the cleanup behavior from `run_convert.sh`.

```bash
mkdir -p "$SHARED_DIR/calibration_images"
mkdir -p "$SHARED_DIR/scripts"
find "$SHARED_DIR" -mindepth 1 -maxdepth 1 ! -name "calibration_images" ! -name "scripts" ! -name "README.md" -delete
rm -rf "$SHARED_DIR/calibration_images"/*
rm -rf "$SHARED_DIR/scripts"/*
chmod -R 777 "$SHARED_DIR"
```

Warning: the `find ... -delete` command removes previous generated artifacts in the root of `shared_with_docker/`.

## 6. Extract training parameters from `args.yaml`

If `args.yaml` exists, use the same extraction logic as the orchestrator:

```bash
if [ -f "$ARGS_YAML" ]; then
    TRAIN_IMGSZ=$(grep "^imgsz:" "$ARGS_YAML" | awk '{print $2}' | tr -d '[]' | cut -d',' -f1)
    TRAIN_CONF=$(grep "^conf:" "$ARGS_YAML" | awk '{print $2}' | head -n1)
    TRAIN_IOU=$(grep "^iou:" "$ARGS_YAML" | awk '{print $2}' | head -n1)
    NUM_CLASSES=$(grep "^nc:" "$ARGS_YAML" | awk '{print $2}' || echo 1)

    [ -z "$TRAIN_IMGSZ" ] || [ "$TRAIN_IMGSZ" = "null" ] && TRAIN_IMGSZ=640
    [ -z "$TRAIN_CONF" ] || [ "$TRAIN_CONF" = "null" ] && TRAIN_CONF=0.25
    [ -z "$TRAIN_IOU" ] || [ "$TRAIN_IOU" = "null" ] && TRAIN_IOU=0.45
    [ -z "$NUM_CLASSES" ] || [ "$NUM_CLASSES" = "null" ] && NUM_CLASSES=1
else
    TRAIN_IMGSZ=640
    TRAIN_CONF=0.25
    TRAIN_IOU=0.45
    NUM_CLASSES=1
fi
```

Check the resolved values:

```bash
printf "imgsz=%s\nconf=%s\niou=%s\nclasses=%s\n" "$TRAIN_IMGSZ" "$TRAIN_CONF" "$TRAIN_IOU" "$NUM_CLASSES"
```

## 7. Activate the Python environment

```bash
source "$VENV_NAME/bin/activate"
```

Optional sanity checks:

```bash
which python
which yolo
python --version
```

## 8. Export `best.pt` to ONNX

This is the same export command used by `run_convert.sh`:

```bash
rm -f /tmp/yolo_export.log
yolo export model="${MODEL_PT}" format=onnx simplify=true imgsz="${TRAIN_IMGSZ}" opset=12 |& tee /tmp/yolo_export.log
```

The expected output file is generated next to `best.pt`:

```bash
ls -lh "$(dirname "$MODEL_PT")/best.onnx"
```

## 9. Move the ONNX file to the shared folder

```bash
mv "$(dirname "$MODEL_PT")/best.onnx" "$SHARED_DIR/best.onnx"
ls -lh "$SHARED_DIR/best.onnx"
```

## 10. Prepare the calibration dataset

This reproduces the selection logic from `run_convert.sh`.

```bash
counter=1
find "$DATASETS_DIR" -type f \( -iname "*.jpg" -o -iname "*.jpeg" -o -iname "*.png" \) | shuf | head -n "$NUM_CALIB_IMAGES" | while read -r img; do
    extension="${img##*.}"
    cp "$img" "$SHARED_DIR/calibration_images/calib_${counter}.${extension}"
    counter=$((counter + 1))
done
```

Confirm how many images were copied:

```bash
find "$SHARED_DIR/calibration_images" -type f | wc -l
```

## 11. Generate `nms_config.json`

This file is generated by the orchestrator even though the compile step itself only depends directly on `best.onnx` and `calibration_images/`.

```bash
cat <<EOF > "$SHARED_DIR/nms_config.json"
{
    "nms_scores_th": ${TRAIN_CONF},
    "nms_iou_th": ${TRAIN_IOU},
    "max_proposals_per_class": 100,
    "classes": ${NUM_CLASSES},
    "background_removal": false,
    "meta_arch": "yolov8"
}
EOF
```

Check the file:

```bash
cat "$SHARED_DIR/nms_config.json"
```

## 12. Copy the compile script to the shared folder

The orchestrator restores the container-side script from the versioned source:

```bash
cp ./convert_flow/scripts/compile.sh "$SHARED_DIR/scripts/compile.sh"
chmod +x "$SHARED_DIR/scripts/compile.sh"
ls -lh "$SHARED_DIR/scripts/compile.sh"
```

## 13. Deactivate the Python environment

```bash
deactivate
```

## 14. Start or resume the Hailo Docker environment

This is the standard host-side command:

```bash
sudo ./convert_flow/run_hailo_docker.sh
```

Important details from `run_hailo_docker.sh`:

- if the image does not exist locally, it tries to load `${DOCKER_TAR_FILE}`
- the tar file is expected at `${PROJECT_ROOT}/${DOCKER_TAR_FILE}`
- `${SHARED_DIR}` is mounted inside the container at `/local/shared_with_docker`
- if the container already exists, the script starts it and opens `/bin/bash`

If you only want the container running without staying attached, you can verify the status from another shell:

```bash
sudo docker ps -a --filter "name=${CONTAINER_NAME}"
sudo docker inspect -f '{{.State.Status}}' "${CONTAINER_NAME}"
```

## 15. Run the HEF compilation manually

The host-side manual command is:

```bash
sudo docker exec -it "${CONTAINER_NAME}" /bin/bash -c "/local/shared_with_docker/scripts/compile.sh ${MODEL_BASE}"
```

This executes the following container-side behavior:

```bash
MODEL_BASE="${1:-yolov8n_seg}"
BASE_DIR="/local/shared_with_docker"
ONNX_MODEL="${BASE_DIR}/best.onnx"
CALIB_PATH="${BASE_DIR}/calibration_images"
HAILO_ARCH="hailo8"

WORKDIR="/tmp/hailo_compile"
rm -rf "$WORKDIR" && mkdir -p "$WORKDIR"
cd "$WORKDIR"
cp "$ONNX_MODEL" .

hailomz compile "${MODEL_BASE}" \
    --ckpt "./best.onnx" \
    --calib-path "${CALIB_PATH}" \
    --hw-arch "${HAILO_ARCH}"
```

If you are already inside the container shell opened by `run_hailo_docker.sh`, the equivalent direct command is:

```bash
/local/shared_with_docker/scripts/compile.sh "${MODEL_BASE}"
```

## 16. Confirm the generated artifacts

Back on the host:

```bash
ls -lh "$SHARED_DIR"/*.hef
ls -lh "$SHARED_DIR"/*.har
```

Typical final directory checks:

```bash
ls -lh "$SHARED_DIR/best.onnx"
find "$SHARED_DIR/calibration_images" -type f | wc -l
cat "$SHARED_DIR/nms_config.json"
```

mkdir -p "$SHARED_DIR/calibration_images"

sudo docker exec -it "${CONTAINER_NAME}" /bin/bash -c "/local/shared_with_docker/scripts/compile.sh ${MODEL_BASE}"

## Notes and caveats

- `run_convert.sh` uses `find ... -delete`, so a manual run should only clean `shared_with_docker/` when you really want to discard previous outputs.
- The compile stage uses `hailomz compile` with `--hw-arch hailo8`.
- `nms_config.json` is generated on the host side for the downstream raw-output pipeline.
- The current `compile.sh` validates `best.onnx` explicitly, but it assumes `calibration_images/` is already populated.
- If the Docker image is not loaded yet, `run_hailo_docker.sh` expects the tar archive named by `DOCKER_TAR_FILE` at the root of `convert_hailo/`.
