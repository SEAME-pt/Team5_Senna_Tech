## 1. Core Concepts & Analogies

### What is COVESA and VSS?
**COVESA** (Connected Vehicle Systems Alliance) is an open industry alliance that develops common standards for connected vehicles. Their flagship project is **VSS (Vehicle Signal Specification)**.

* **The Problem:** Without a standard, one engineer names the speed signal `car_speed`, another names it `veh_velocity`, and a third uses `v_kmh`. This makes it impossible for apps to run on different car softwares models.
* **The Solution (VSS):** VSS is the **"Dictionary"**. It defines a standard tree structure for data.
    * *Example:* `Vehicle.Speed` is always the standard name, it is always a `float`, and always in `km/h`.
* **The `.vspec` File:** This is the file format where this "Dictionary" is written. It uses YAML syntax to define the hierarchy (e.g., `Vehicle.Cabin.Door.Row1.Left.IsOpen`).

### What is Protobuf and Why do we need it?
**Protocol Buffers (Protobuf)** is a mechanism for serializing structured data. It acts as the "Universal Translator" or "Standard Envelope" for your data.

#### The "Tower of Babel" Analogy
If you try to send raw C++ structures over the network (Wi-Fi/4G), you encounter the "Tower of Babel" problem:
1.  **Endianness:** A standard Intel CPU reads numbers right-to-left. A car ECU might read left-to-right. Sending a raw number like `1` might arrive as `256` or garbage.
2.  **Padding:** C++ compilers add empty spaces between variables to optimize memory. These spaces differ between computers.

#### The Solution
* **The `.vspec` file** is the **Law**.
* **The `.pb.cc` (C++) file** is the **Translator** generated by the tool.
* **The `.pb` packet** is the **Message** written in a universal language (binary) that any machine (Python, Java, Rust, C++) can understand perfectly, regardless of its internal architecture.

## 2. Environment Setup

### Prerequisites
* `Python 3`
* `pip`
* `protoc` (The Protocol Buffers Compiler)

### Installation Step-by-Step

#### 1. Install the Protobuf Compiler
On Ubuntu/Debian/WSL:
```bash
sudo apt update && sudo apt install -y protobuf-compiler
```

#### 2. Clone the Repositories

You need two repositories: the tool (vss-tools) and the official specification (vehicle_signal_specification).
```bash
git clone [https://github.com/COVESA/vss-tools.git](https://github.com/COVESA/vss-tools.git)
git clone [https://github.com/COVESA/vehicle_signal_specification.git](https://github.com/COVESA/vehicle_signal_specification.git)
```
#### 3. Set up Python Environment
Navigate to the tools folder and install dependencies using a virtual environment.

```bash
cd vss-tools

# Create virtual environment
python3 -m venv venv

# Activate it
source venv/bin/activate

# Install the tool in editable mode
pip install .
```

## 3. Generating the Code
We will convert the official VSS standard (YAML) into a Protobuf definition (.proto), and then into C++ code (.cpp/.h).This can be converted to other languages, since we use C++ this was the chosen language.

#### Step 1: Generate the .proto file
Run the vspec export command. We must point to the official specification and include he Unit and Quantity dictionaries to avoid validation errors (e.g., "km/h is not valid").

```bash
vspec export protobuf \
  --vspec ../vehicle_signal_specification/spec/VehicleSignalSpecification.vspec \
  -I ../vehicle_signal_specification/spec \
  -u ../vehicle_signal_specification/spec/units.yaml \
  -q ../vehicle_signal_specification/spec/quantities.yaml \
  --output vss_official.proto
```

Result: You now have **vss_official.proto**, a file describing the entire vehicle data structure in the Protobuf language.

#### Step 2: Compile to C++
Use the Google compiler (protoc) to generate the C++ classes.

```bash
protoc --cpp_out=. vss_official.proto
```

Result:

vss_official.pb.h: The header file you include in your code.

vss_official.pb.cc: The source code that handles the binary translation.

## 4. Summary of Workflow
Define: Architects define signals in .vspec (YAML).

Export: Developers run vspec export protobuf to get the .proto file.

Compile: Run protoc to generate C++ (or Python/Java) libraries.

Implement: Import the generated library into your project to ensure Type Safety and Interoperability.

Transmit: Send the serialized binary data via efficient transports like Zenoh.
