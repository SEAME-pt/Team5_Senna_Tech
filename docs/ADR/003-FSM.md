# [ADR-003] Finite State Machine (FSM) with Historical Confirmation Buffers
Status: Accepted

Date: 21-04-2026

### 1. Context and Problem Statement
Object and sign detection models operating on edge devices are inherently prone to frame-to-frame detection flickering caused by lighting variations, motion blur, or temporary occlusions. If the high-level decision framework reacts instantaneously to every raw detection or momentary loss of signal, the vehicle will display highly unstable behaviors such as erratic braking or constant, rapid speed state switches.

### 2. Considered Options
Option A: Reactive execution (state transitions occur immediately upon detecting a class matching an area threshold).

Option B: Explicit State FSM paired with historical validation buffers (ConfirmationBuffer).

### 3. Decision Outcome
Chosen Option: **Option B**, because validating environmental context over time is crucial for physical prototyping safety. The VehicleFSM uses a circular queue (deque) to track the continuity of raw detections across consecutive frames. A state change is only executed once the corresponding buffer is completely filled with positive confirmations.

### 4.Pros and Cons of the Options
**Option B:** FSM with Confirmation Buffers
* Good: Effectively filters out single-frame classification spikes and false positives.

* Good: Hysteresis logic prevents rapid oscillation between adjacent states (e.g., entering and exiting the FOLLOW state).

* Bad: Introduces a state transition latency proportional to the buffer size and execution loop rate.
